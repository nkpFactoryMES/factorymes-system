# 집의6GB GPU로 제조 데이터 분석을 연결한 과정

처음에는 API 키가 없는 상태에서도 업무 흐름을 확인하려고 Mock 분석을 만들었다. 실제 모델을 붙이는 단계에서는 ‘LLM을 실행하면 예지보전이 되는가’부터 구분했다. 수집 중인 온도·카운터와 정지·경보 이력은 있었지만 고장 라벨과 잔여수명 정답은 없었다. 따라서 고장 확률을 생성하는 대신 현재 상태를 근거와 함께 점검하는 기능으로 범위를 정했다.

Ollama와 llama.cpp 직접 실행, .NET 수치 모델을 비교했다. 단순히 어떤 제품이 더 좋은지를 묻기보다6GB메모리에 들어오는 모델, C#서비스와의 연결, CUDA/모델 파일 관리 책임, 예측을 검증할 데이터, 추후 교체 범위를 기준으로 살폈다. 기존 HTTP Connector 경계를 활용하고 모델 관리를 줄이기 위해 Ollama와 Qwen2.5 1.5B Q4를 선택했다. 다른 런타임과 동일 조건 성능 대결을 한 선택은 아니다.

업무 Backend가 Oracle 집계 스냅샷과 입력 해시를 확정하고 Gateway를 거쳐 AI Connector로 보낸다. Connector는 내부 로컬 모델에 점검 근거만 전달해 설명을 생성한다. 위험도는 고정된 시연 정책으로 계산하고 Backend가 다시 계산해 반환 결과를 검증한다. AI의 문장과 업무 판단의 권위를 분리한 것이다. 결과는 담당자 검토 대상으로 보관하며 실제 경보·설비 제어를 자동 실행하지 않는다.

검토 과정에서 전체 수집률이 온도 수집률을 뜻하지 않는 문제를 발견했다. 카운터는 정상이어도 온도만 오래된 경우를 구분하기 위해 LOCAL 스냅샷에 지표별 표본·관측률·마지막 시각을 추가했다. 기존 Mock에는 선택 필드를 생략해 과거 입력 해시를 보존했다. 온도 근거가 부족하면UNKNOWN으로 보류한다.30/35°C 경계는 실제 제조사 한계가 아닌 시연 정책으로 명시했다.

실제1660Ti에서 모델을 실행했고 GPU상주와100%GPU표시를 별도로 확인했다. 정상 추론 컨테이너는 호스트 포트와 인터넷 없이 내부망에서만 접근한다. 모델 다운로드 때만 외부망을 연결하고 완료 후 제거한다. API 키·유료 서비스 없이 로컬 모델을 실행했으며 모델 서버를 실제로 중지했다 복구해도 같은 입력으로 재시도하고 결과·알림을 하나만 저장하는 것을 확인했다.

Claude는 Gateway·관리자 화면·브라우저 검증과 읽기 전용 독립 검토를 맡았고 GPT는 Backend·Contracts·Connector·Compose·GPU설치·통합 검증을 나눠 진행했다. 파일 소유권을 공유 문서로 정하고 공통 빌드·컨테이너 조작은 한 담당만 실행해 동시 수정을 피했다. 최종392개 검사를 통과했고11서비스가 정상 상태다. 이 수에는 순수 계약 검사와 실제 GPU·Oracle·브라우저 검사가 섞여 있으므로 상세 문서에서 범위를 각각 구분한다.

이번 결과는 실제 로컬 모델 연동과 근거를 보존하는 상태 점검의 구현이다. 학습된 고장 예측이나 잔여수명 추정의 정확도를 입증한 것은 아니다. 다음에는 실제 정상·고장 이력과 설비별 정비 기준이 확보됐을 때 수치 예측 모델과 오차를 비교해야 한다. 선택 이유·변경한 판단·실패한 시험·재현 명령·증거는 [상세 비교·구현·검증](local-ai-maintenance-decision.md)와 날짜별 협업 기록에 남겼다.
