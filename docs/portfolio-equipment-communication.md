# 설비 수집을 Modbus TCP 어댑터로 확장한 과정

## 개요

FactoryMES는 관리자가 연결 정보를 등록하면 Oracle 설정이 Redis·연동 Gateway를 거쳐
Connector에 반영되고, 수집한 값이 경보·AUTO 생산실적·마감 통계로 이어지는 프로젝트다.
초기에는 HTTP Mock으로 업무 흐름을 검증했지만, 실제 산업 통신의 주소·자료형·장애 처리를
설명할 근거가 부족했다. 무료 로컬 환경에서 실제 프로토콜까지 다루는 것을 다음 목표로 잡았다.

## Modbus TCP와 OPC UA를 비교한 이유

둘 다 C#에서 사용할 수 있어 언어만으로 결정할 수 없었다. 필요한 값의 의미, 주소/자료형,
polling과 구독, 시간·품질 정보, 장애 복구, 장치 보안, 비용, 기존 서비스 변경 범위를 비교했다.
OPC UA는 Node 정보 모델과 구독·보안 구성이 유용하지만, 당시 요구는 누적 카운터·온도를
기존 MES 원장까지 연결하는 것이었다. UA를 선택하면 모델·session·구독·인증서 운영까지
같이 검증해야 했고 이를 요구하는 실제 장치 모델은 아직 없었다.

그래서 이번에는 Modbus TCP의 FC03 읽기를 먼저 구현했다. OPC UA를 유료라서 제외한 것은
아니다. 무료 .NET 구현도 확인했으며, 필요한 정보 모델이나 구독 요구가 생기면 다시 검토하기로 했다.

## 기존 구조의 변경 범위를 제한한 방식

Gateway에 소켓 통신을 넣기보다 Connector에 IEquipmentReader를 두고 HTTP·Modbus 읽기를
분리했다. 어댑터는 장치 읽기와 표준 값 변환을 맡고 기존 Collector는 lease·서명·이벤트 ID·
재전송·ACK를 관리한다. Backend의 중복 방지·AUTO 원장·경보는 같은 경로를 사용한다.

설정에는 0기반 주소·자료형·byte/word 순서를 명시하고125 registers 이내를 한 FC03으로 읽었다.
카운터는 unsigned 정수·배율1·오프셋0을 요구해 잘못된 설정이 매번 실패하지 않도록 했다.
Modbus의 수집 완료 시각을 PLC 원천 timestamp로 설명하지 않았으며 장치 자체의 정상 품질과도 구분했다.

## 라이브러리도 실제 오류 응답으로 확인했다

무료 NModbus를 사용하되 독립 TCP peer로 응답을 바꿔 보내 보았다. 사용 버전에서 잘못된
MBAP protocol ID와 payload 내 추가 byte를 받아들이는 경우를 확인했다. 전체 client를 직접
만들기보다 FC03 framing만 검사하고 기존 요청 생성·transaction/unit 검증은 재사용하는 작은
보강을 적용했다. 변경 전 수용하던 응답이 거절되고 정상 분할 수신·timeout·취소는 유지되는지 확인했다.

## 실제 수집과 업무 결과

NModbus client와 별개의 BCL simulator를 만들고 실제 TCP/MBAP/FC03으로 수집했다.
관리자 폼에서 연결·태그를 등록하고 배율을 바꾸면 새 설정 버전의 측정이 저장되며 과거 이력도 남는다.
같은 unit을 다른 설비로 등록하면 원인을 보여 주고 입력값을 보존한다.

Simulator를 정지했을 때 새 GOOD 자료를 만들지 않고 RETRYING으로 표시했다. 재기동으로 카운터가
낮아지면 기존 AUTO가 합산을 멈추고 사유 있는 재확인을 요구한다. 새 기준 뒤 생산을 재개하고
작업자 불량 입력·제출·관리자 마감·일별 통계까지 원장과 대조했다.

## 검증 결과와 다음 범위

프레임/변환93·실제 수집/장애/실적65·Modbus화면12·기존HTTP/API227·기존화면25로
422개 통합 단언이 통과했다. 전체12프로젝트 빌드 경고/오류0,10개 서비스 healthy를 확인했다.
실제 장비 대신 로컬 simulator를 사용했으며 PLC 제조사별 호환·고부하·TLS·OPC UA와
Modbus별 경보 전체 수명주기를 검증했다고 주장하지 않는다.

다음에 실제 UA 장치·Node 모델·원천 품질·구독 이벤트가 필요해지면 session 수명과 인증서·
재전송/중복까지 포함해 확장한다. 지금의 polling 인터페이스에 구독을 억지로 맞추지 않는다.

분리했다. 공유 기록에는 Claude와 GPT의 파일 분담, 검토 의견과 실제 반영/재검증을 남겼다.
